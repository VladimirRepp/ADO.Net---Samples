# ADO.NET + MySQL — Business Logic Sample

Учебный проект на C#, Windows Forms, ADO.NET и MySQL, предназначенный для изучения взаимодействия бизнес-логики приложения с базой данных.

## 1. О проекте

Приложение представляет собой одно окно с несколькими вкладками:

- **Калькулятор** — выполнение арифметических операций.
- **Конвертер температуры** — перевод значений между градусами Цельсия (°C), Фаренгейта (°F) и Кельвина (K).

Код разделён на логические слои, чтобы отделить пользовательский интерфейс от вычислений и взаимодействия с базой данных.

Главная цель проекта — показать, как приложение может использовать базу данных для работы с бизнес-логикой, не сводя всё взаимодействие с БД к стандартным CRUD-операциям.

**Репозиторий:** [ADO.Net — Samples / Sample_2](https://github.com/VladimirRepp/ADO.Net---Samples/tree/main/ADO.Net%20-%20MySQL/Sample_2)

## 2. Технологии

| Технология | Назначение |
|---|---|
| C# | Язык программирования |
| Windows Forms | Создание графического интерфейса |
| ADO.NET | Доступ к данным и выполнение SQL-команд |
| MySQL | Реляционная база данных |
| MySQL ADO.NET Provider | Подключение C# к MySQL |

В зависимости от используемого в проекте провайдера работа с MySQL может выполняться через классы `MySqlConnection`, `MySqlCommand`, `MySqlDataReader` и другие классы соответствующего пространства имён.

## 3. Что изучаем в проекте

После изучения исходного кода студент должен понимать:

- Как разделять приложение на логические слои.
- Чем пользовательский интерфейс отличается от бизнес-логики.
- Как организовать вычисления отдельно от формы.
- Как приложение подключается к MySQL через ADO.NET.
- Как выполнять SQL-команды из C#.
- Как передавать данные между слоями.
- Как обрабатывать пользовательский ввод и ошибки.
- Как использовать базу данных в рамках прикладного сценария, а не только для добавления, чтения, изменения и удаления записей.

## 4. Архитектура приложения

Основной принцип проекта — **разделение ответственности**.

Каждый слой должен отвечать за свою часть работы. Это упрощает понимание кода, тестирование и дальнейшее развитие приложения.

### Уровень 1. Пользовательский интерфейс (UI)

**Технология:** Windows Forms.

Отвечает за взаимодействие с пользователем:

- отображение вкладок и элементов управления;
- получение введённых значений;
- обработку нажатий кнопок;
- передачу данных в соответствующую логику;
- отображение результатов и сообщений об ошибках.

Форма не должна содержать всю бизнес-логику приложения.

Например, обработчик кнопки конвертации должен получать введённое значение и вызывать соответствующий метод, а не превращаться в место хранения всех формул и правил вычисления.

### Уровень 2. Бизнес-логика (Business Logic)

Отвечает за правила работы приложения.

Примеры ответственности:

- выполнение арифметических вычислений;
- перевод температуры между единицами измерения;
- проверка допустимости операций;
- подготовка данных для дальнейшей обработки;
- выполнение прикладных сценариев, связанных с базой данных.

Бизнес-логика не должна зависеть от конкретного расположения кнопок, текстовых полей и вкладок.

Это позволяет использовать одну и ту же логику из разных интерфейсов.

### Уровень 3. Доступ к данным (Data Access)

Отвечает за взаимодействие с MySQL.

В зависимости от реализации проекта этот уровень может включать:

- открытие соединения с базой данных;
- создание и выполнение SQL-команд;
- передачу параметров запросов;
- получение результатов;
- обработку ошибок доступа к данным.

Именно здесь следует искать код, связанный с ADO.NET и SQL-запросами.

Важно: не следует переносить SQL-запросы непосредственно в обработчики кнопок формы, если для доступа к данным предусмотрен отдельный слой.

### Общая схема взаимодействия

```text
Пользователь
     |
     v
Windows Forms (UI)
     |
     v
Бизнес-логика
     |
     v
Слой доступа к данным
     |
     v
MySQL Database
```

Результат возвращается в обратном направлении: от базы данных через соответствующие слои к пользовательскому интерфейсу.

При этом не каждый сценарий обязан обращаться к БД. Например, обычное арифметическое вычисление может выполняться исключительно в бизнес-логике.

## 5. Бизнес-логика и база данных — не только CRUD

CRUD — это четыре базовые операции над данными:

| Операция | Значение | SQL |
|---|---|---|
| Create | Создание записи | `INSERT` |
| Read | Чтение данных | `SELECT` |
| Update | Изменение записи | `UPDATE` |
| Delete | Удаление записи | `DELETE` |

В реальных приложениях взаимодействие с базой данных часто является частью более сложного бизнес-сценария.

Например, приложение может:

1. Получить пользовательские данные.
2. Проверить допустимость операции.
3. Получить необходимые сведения из БД.
4. Выполнить вычисления или применить бизнес-правила.
5. Сохранить результат, если этого требует сценарий.
6. Вывести пользователю итог.

Не каждый сценарий требует всех шести шагов. Их последовательность определяется задачей.

**При изучении проекта:** найди конкретный сценарий, в котором бизнес-логика взаимодействует с БД, и проследи его от обработчика события в форме до SQL-команды и обратно.

Необходимо понять не только то, какой запрос выполняется, но и зачем он нужен приложению.

## 6. ADO.NET: основные понятия

ADO.NET предоставляет классы для подключения к источнику данных и выполнения команд.

### `Connection`

Представляет соединение с базой данных.

Пример для провайдера `MySql.Data`:

```csharp
using MySql.Data.MySqlClient;

using var connection =
    new MySqlConnection(connectionString);

connection.Open();
```

`connectionString` содержит параметры подключения к серверу и базе данных.

Не открывай соединение без необходимости и своевременно освобождай ресурсы.

### `Command`

Представляет SQL-команду, выполняемую через соединение.

```csharp
using var command = new MySqlCommand(
    "SELECT COUNT(*) FROM ExampleTable",
    connection);

object? result = command.ExecuteScalar();
```

Этот пример демонстрирует получение одного значения — количества записей в таблице.

`ExecuteScalar()` возвращает первое значение первой строки результата. Он удобен для запросов, возвращающих одно значение.

### `DataReader`

Используется для последовательного чтения результата SQL-запроса.

Основной принцип работы:

1. Выполнить запрос.
2. Получить объект чтения.
3. Последовательно прочитать строки.
4. Извлечь нужные значения.

### Параметризованные запросы

Если SQL-команда использует значения, полученные от пользователя или из других источников, передавай их через параметры.

Пример:

```csharp
using var command = new MySqlCommand(
    "SELECT Id FROM ExampleTable WHERE Name = @name",
    connection);

command.Parameters.AddWithValue("@name", name);

object? result = command.ExecuteScalar();
```

Параметры помогают корректно передавать значения и защищают от SQL-инъекций при правильном использовании.

Не формируй SQL-запрос объединением строк с пользовательским вводом.

> Примеры выше иллюстрируют отдельные возможности ADO.NET. Перед использованием их необходимо адаптировать к реальной структуре базы данных и выбранному в проекте провайдеру.

## 7. Работа с температурой

Конвертер позволяет разобраться в разделении вычислений и пользовательского интерфейса.

Основные формулы:

### Цельсий → Фаренгейт

\[
F = C \times \frac{9}{5} + 32
\]

### Фаренгейт → Цельсий

\[
C = (F - 32) \times \frac{5}{9}
\]

### Цельсий → Кельвин

\[
K = C + 273.15
\]

### Кельвин → Цельсий

\[
C = K - 273.15
\]

### Фаренгейт → Кельвин

\[
K = (F - 32) \times \frac{5}{9} + 273.15
\]

### Кельвин → Фаренгейт

\[
F = (K - 273.15) \times \frac{9}{5} + 32
\]

При изучении реализации обрати внимание на следующие моменты:

- где выполняется преобразование введённого текста в число;
- где находятся формулы;
- как определяется исходная и целевая единица измерения;
- как обрабатываются некорректные значения;
- как результат возвращается в форму.

**Важный нюанс:** физическая температура в кельвинах не может быть отрицательной. Если приложение должно соблюдать физические ограничения, эту проверку следует реализовать на уровне бизнес-логики.

## 8. Работа с калькулятором

Калькулятор — простой пример прикладной логики.

При изучении реализации проверь:

- как определяется выбранная арифметическая операция;
- где выполняются вычисления;
- как обрабатываются деление на ноль и другие недопустимые ситуации;
- как результат передаётся в интерфейс;
- какие проверки выполняются до вычисления.

Полезно сравнить два подхода:

**Неудачный вариант:** форма самостоятельно проверяет все условия, выполняет вычисления, обращается к БД и формирует результат.

**Более удобный вариант:** форма получает пользовательский ввод, передаёт его соответствующему слою и отображает полученный результат.

Второй подход упрощает поддержку кода и позволяет повторно использовать бизнес-логику.

## 9. Работа с базой данных

При самостоятельном изучении найди в проекте:

- строку подключения;
- класс или метод, отвечающий за подключение;
- SQL-запросы;
- методы выполнения команд;
- места, в которых результат запроса используется бизнес-логикой;
- обработку ошибок подключения и выполнения запросов.

Для каждого SQL-запроса ответь на три вопроса:

1. **Что делает запрос?** Например, получает значение, проверяет условие или сохраняет результат.
2. **Почему он нужен приложению?** Какую прикладную задачу решает?
3. **Кто вызывает запрос?** Форма, бизнес-логика или другой компонент?

Именно третий вопрос помогает понять архитектуру проекта.

Если данные или результаты вычислений сохраняются в БД, выясни, почему они должны храниться и как используются при следующем обращении к приложению.

Если запрос только читает данные, определи, какое решение или вычисление зависит от полученного результата.

## 10. Подключение к MySQL

Чтобы запустить проект на другом компьютере:

1. Установи MySQL Server или подготовь доступный сервер MySQL.
2. Открой проект в Visual Studio.
3. Найди настройки подключения к базе данных.
4. Проверь имя сервера, порт, имя базы данных и учётные данные.
5. Создай необходимую структуру БД, используя SQL-скрипт проекта, если он присутствует.
6. Проверь наличие нужных таблиц и начальных данных.
7. Восстанови NuGet-пакеты, собери проект и запусти приложение.

Если SQL-скрипта нет, необходимо изучить SQL-запросы и требования исходного кода, чтобы определить нужную структуру БД.

Не публикуй реальные пароли и другие секреты подключения в GitHub. Для учебной и рабочей среды используй подходящий способ внешней настройки строки подключения.

### Этап 2. Бизнес-логика

- Найди классы, отвечающие за вычисления.
- Определи, какие данные они принимают.
- Посмотри, что возвращают методы.
- Проверь, зависят ли они от Windows Forms.

### Этап 3. Доступ к данным

- Найди код подключения к MySQL.
- Изучи используемые классы ADO.NET.
- Разбери каждый SQL-запрос.
- Проследи передачу параметров и получение результатов.

### Этап 4. Полный сценарий

Выбери одну функцию приложения и проследи весь путь:

```text
Действие пользователя
        ↓
Обработчик события
        ↓
Бизнес-логика
        ↓
Доступ к БД (если требуется)
        ↓
Результат операции
        ↓
Отображение в интерфейсе
```

Не ограничивайся чтением отдельных классов. Важно понять, как они взаимодействуют друг с другом.

## 14. Итог

Этот проект следует рассматривать не просто как калькулятор и конвертер температуры, а как учебный пример организации настольного приложения с разделением ответственности и взаимодействием с MySQL.

При изучении важно понять три принципа:

- **UI отвечает за взаимодействие с пользователем.**
- **Бизнес-логика отвечает за правила и вычисления.**
- **Слой доступа к данным отвечает за взаимодействие с базой данных.**

Главная цель — научиться прослеживать полный сценарий работы программы и понимать, почему каждый участок кода находится именно в своём слое.

После этого будет проще разрабатывать более крупные приложения на C#, WinForms и ADO.NET, в которых бизнес-логика существенно сложнее простых вычислений.
